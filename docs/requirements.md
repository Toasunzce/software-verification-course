Данный проект - бэкенд-сервис для поиска информации и получения ответов по загруженным документам.

Ключевой проблемой, которую решает данный сервис - поиск и конкретный ответ на пользовательские вопросы. Поисковые системы не способны дать ответ на поставленный вопрос, однако они могут направить на релевантный источник информации. RAG и LLM подходы позволяют решить эту проблему использованием поиска осмысленных чанков и генерацию ответа с учетом контекста.

## Цели:
- BR-1. Находить фрагменты документов по смыслу запроса, а не по точному совпадению слов.
- BR-2. Отвечать на вопросы на естественном языке, опираясь только на содержимое загруженных документов.
- BR-3. Давать краткое представление о документе (резюме и тема) без его полного прочтения.
- BR-4. Работать на обычном процессоре без использования сторонней GPU.

## Пользовательские требования:
- UR-1. Загрузить документ в поддерживаемом формате.
- UR-2. Проиндексировать документ, чтобы он стал доступен для поиска.
- UR-3. Искать фрагменты документов по смыслу запроса.
- UR-4. Задать вопрос и получить ответ на основе содержимого документов.
- UR-5. Получить краткое резюме документа.
- UR-6. определить тему текста.
- UR-7. Просмотреть список документов и их состояние.
- UR-8. Архивировать документ.
- UR-9. Удалить документ.

## Функциональные треблвания
- FR-1. `POST /documents` принимает файл, создает документ со статусом `uploaded` и возвращает ответ с кодом `201` и идентификатором документа `id`.
- FR-2. Сервис поддерживает загрузку файлов в форматах `pdf`, `docx`, `html`, `htm`, `txt`, `md`; регистр расширения файла не учитывается.
- FR-3. Файл неподдерживаемого формата отклоняется с кодом `415`, при этом файл не сохраняется на диск.
- FR-4. Пустой файл размером `0` байт отклоняется при загрузке с кодом `422`.
- FR-5. Файл размером более `10` МБ отклоняется с кодом `413`.
- FR-6. `GET /documents` возвращает список документов; параметр `status` позволяет отфильтровать список по статусу документа.
- FR-7. `GET /documents/{id}` возвращает информацию о документе; для несуществующего `id` возвращается код `404`.
- FR-8. `POST /documents/{id}/index` доступен для документов со статусами `uploaded` и `failed`; во время обработки документ переходит в статус `processing`, а после успешного завершения — в `indexed`.
- FR-9. При успешной индексации чанки документа и их эмбеддинги сохраняются в векторном хранилище, а в записи документа заполняются поля `chunks_count` и `category`.
- FR-10. При возникновении ошибки во время индексации документ переводится в статус `failed`, а причина ошибки сохраняется в поле `error`.
- FR-11. Повторная индексация документа со статусом `processing`, `indexed` или `archived` отклоняется с кодом `409`.
- FR-12. `POST /search` возвращает не более `top_k` наиболее релевантных фрагментов документов; значение `top_k` по умолчанию равно `4`. Каждый результат содержит текст фрагмента, `document_id`, `chunk_index` и `score`. Результаты возвращаются в порядке убывания близости.
- FR-13. Параметр `top_k` со значением вне диапазона от `1` до `20`, а также пустой параметр `query` отклоняются с кодом `422`.
- FR-14. Параметр `document_id` в запросах `/search` и `/ask` ограничивает поиск одним документом; для несуществующего документа возвращается код `404`.
- FR-15. Архивные документы не участвуют в поиске и не используются при формировании ответов на вопросы.
- FR-16. `POST /ask` формирует ответ с использованием LLM на основе найденных релевантных фрагментов и возвращает ответ вместе с источниками.
- FR-17. Если релевантные фрагменты не найдены, `/ask` возвращает стандартное сообщение об отсутствии информации без обращения к LLM.
- FR-18. `GET /documents/{id}/summary` доступен только для документов со статусом `indexed`; для документов с другими статусами возвращается код `409`.
- FR-19. Резюме документа генерируется при первом запросе и сохраняется. При последующих запросах возвращается сохраненное резюме без повторного обращения к LLM.
- FR-20. `POST /classify` определяет категорию текста, возвращая одну категорию из настроенного списка и оценку близости.
- FR-21. `POST /documents/{id}/archive` переводит документ из статуса `indexed` в `archived` и удаляет связанные с ним векторы. Для документов с другими статусами возвращается код `409`.
- FR-22. `DELETE /documents/{id}` удаляет запись документа, связанный файл и его векторы, после чего возвращает код `204`. Для несуществующего `id` возвращается код `404`.
- FR-23. Каждый запрос к `/search` и `/ask` сохраняется в истории запросов с указанием типа и текста запроса.

## Нефункциональные требования
| ID | Категория | Требование |
|---|---|---|
| NFR-1 | Производительность | Семантический поиск по базе до 1000 чанков выполняется не более 2 секунд на CPU (без учета первого запроса после старта) |
| NFR-2 | Окружение | Сервис работает на компьютере без GPU |
| NFR-3 | Надежность | Недоступность или ошибка Groq API приводит к ответу 502 с описанием ошибки, остальные эндпоинты продолжают работать |
| NFR-4 | Единообразие ошибок | Все ошибки возвращаются в JSON с полем `detail` и соответствующим HTTP-кодом, без стек-трейса в ответе |
| NFR-5 | Сопровождаемость | Реализации `Embedder`, `VectorStore`, `LLMClient`, `DocumentLoader` заменяются без изменения кода сервисов (зависимости передаются через конструктор) |
| NFR-6 | Переносимость | Запуск на Windows и Linux по инструкции из README, Python 3.11 и выше |
| NFR-7 | Безопасность | Ключ Groq API хранится в `.env`, исключен из репозитория через `.gitignore` и не возвращается в ответах API |
